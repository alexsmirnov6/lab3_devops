# Проверка после рефакторинга

Дата: 18 октября 2026. Среда: Windows-11-10.0.26200-SP0; Python 3.14.3.

Вход: `data/prepared/devops_vacancies.ndjson`, 1880228 байт; SHA-256: `5c9daf1ac2c16c3aad36d97e6e23c7cffc6d92f0cf4ca215d73f8140e721b0c7`.

MapReduce читает данные через boto3 с локального HTTP-стенда с HEAD и Range GET; используется настоящий ProcessPoolExecutor. DuckDB выполняет тот же SQL подсчёта, но читает локальный файл. Это проверка алгоритма и локальные замеры, а не повтор эксперимента с RustFS/httpfs. Старые журналы RustFS оставлены без изменений.

Каждая строка — медиана 3 последовательных запусков. Время включает запуск Python, создание процессов и запись JSON. RSS — максимум суммы памяти дерева процессов с шагом 10 мс; общие страницы могут учитываться несколько раз.

Для 1 процесса и чанка 1 МиБ combiner уменьшил объём Pickle на 63.3%; отношение медиан времени baseline/optimized — 1.06.

Размер Pickle — сумма сериализованных payload успешных Mapper, без служебных полей и обрамления IPC. Дополнительная сериализация для метрики включена во время. При уменьшении чанков combiner видит меньше записей за задачу; одна и та же комбинация может передаваться в Reducer из нескольких чанков.

При чанке 1 МиБ здесь всего две задачи: четыре процесса не получают больше двух задач. Эти данные не позволяют делать вывод о масштабировании на большом наборе. На время влияют запуск процессов Windows, сериализация и запись результатов; меньшее число элементов само по себе не гарантирует ускорения.

Искусственный отказ второго чанка: 1 повтор, 6215 записей, результат совпал с DuckDB.

Для каждого запуска baseline и optimized проверены полные JSON документов skills, pairs и triples. Совпали также SHA-256 результатов из исходного `evidence/verification.json`: 1 541 навык, 25 462 пары, 195 366 троек, 6 215 вакансий.

DuckDB (локальный файл, 4 потока): медиана 1.058 с, 295.1 МиБ RSS. Сравнивать это время с S3/httpfs как равные условия нельзя.
