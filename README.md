# Анализ вакансий DevOps в RustFS

Лабораторная работа 3, вариант 11. Проект обрабатывает вакансии DevOps и
сравнивает собственную реализацию MapReduce с аналитикой SQL в DuckDB. Данные
хранятся в RustFS и читаются через S3 API.

## Отчёт

[Распределённый анализ вакансий DevOps](report/lab3_devops.pdf) описывает данные,
подготовку, MapReduce, проверки, профилирование, зарплаты и три региона. В отчёте
приведены результаты проверок и ссылки на документацию. Их не требуется
восстанавливать из истории переписки.

## Данные и отбор

Исходный `it_vacancies_2024.csv` размером 847 619 384 байта не входит в репозиторий.
SHA-256: `303db922b541e4440906f5a7e8be32fb55e8808f950ffddb8c272f1548212a65`.
Положите CSV рядом с каталогом проекта или передайте его путь в PowerShell-сценарий.

Критерий варианта отбирает названия DevOps/DevSecOps, «девопс», SRE,
Site Reliability и Platform Engineer. Python готовит одну запись NDJSON на вакансию;
навыки нормализуются и очищаются от повторов. DuckDB отдельно проверяет
отфильтрованный набор ID запросом к исходному CSV.

## Расчёт

MapReduce читает NDJSON через S3 Range GET, считая навыки, пары и тройки.
Неполные строки на границах диапазонов дочитываются до конца записи. `baseline`
передаёт все комбинации, а `optimized` предварительно объединяет повторяющиеся
значения в Mapper с помощью combiner. DuckDB независимо считает те же комбинации
в SQL через расширение `httpfs`.

При рабочем Docker Desktop выполните полную проверку:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
# Заполните RUSTFS_ACCESS_KEY и RUSTFS_SECRET_KEY в .env
.\scripts\validate_rustfs.ps1
```

Сценарий запускает RustFS, загружает исходный CSV и подготовленный NDJSON,
считает три варианта результата, проверяет их через DuckDB, тестирует повтор
после отказа Mapper и выполняет по три измерения каждого метода. Он также
загружает `skills.json`, `pairs.json`, `triples.json` в `results/mapreduce/`,
скачивает их из S3 и сверяет размеры и SHA-256. Вывод команд и JSON-доказательства
сохраняются в `evidence/rustfs-validation/`.

Для подготовки данных вручную:

```powershell
python src/prepare_dataset.py ..\it_vacancies_2024.csv --out-dir data/prepared
```

Основные команды для отдельных шагов приведены в `scripts/validate_rustfs.ps1`.
Сценарий не выполняет Git-команды. Локальные ключи, данные RustFS и результаты
вычислений не добавляются в репозиторий.

## Проверки без RustFS

Регрессионные тесты используют небольшой локальный Range GET-стенд и проверяют
границы чанков, длинные строки, два режима MapReduce и восстановление после отказа:

```powershell
python -X utf8 -m unittest discover -s tests -v
```

Полный измерительный эксперимент без доступа к RustFS можно выполнить отдельно:

```powershell
python -X utf8 tests/run_experiments.py --attempts 3
```

В этом опыте Range GET обслуживает локальный HTTP-стенд, а DuckDB читает файл.
Результаты сохранены в `evidence/local_experiments.json` и описаны в
`evidence/experiment_notes.md`; эти цифры не являются замерами RustFS.

## Основные показатели

В сегменте 6 215 вакансий. Полные результаты содержат 1 541 уникальный навык,
25 462 пары и 195 366 троек. Суммы частот равны 35 158, 173 204 и 687 102:
каждый раз, когда комбинация встречается в новой вакансии, частота увеличивается,
хотя уникальный ключ остаётся тем же.

Последние замеры на RustFS: медиана времени MapReduce baseline - 2,098 с,
с combiner - 2,047 с, DuckDB `httpfs` - 1,047 с. Combiner уменьшил сериализованные
промежуточные данные на 55,4%. Пик RSS составил 411,2, 366,3 и 323,9 МиБ
соответственно. Измерялась сумма RSS дерева процессов с интервалом 10 мс; общие
страницы могут учитываться повторно. Эти значения относятся к данному компьютеру,
локальному хранилищу и размеру выборки.

Региональный отчёт содержит топ-5 пар и троек для Москвы, Санкт-Петербурга и
Екатеринбурга. Для каждой комбинации указаны абсолютная частота и доля как среди
вакансий с навыками, так и среди всех вакансий региона. Зарплатная разница между
медианой сочетания и медианой базы показывает наблюдаемую связь, но не причинный
эффект навыка. Оплата раскрыта только для 1 364 вакансий.

## Структура проекта

- `src/prepare_dataset.py` - фильтрация и подготовка NDJSON;
- `src/mapreduce_s3.py` - MapReduce с Range GET, combiner и повтором временных сбоев;
- `src/duckdb_counts_s3.py` - SQL-подсчёт в DuckDB;
- `src/duckdb_analysis.py` - зарплаты и региональные сочетания;
- `src/s3_io.py` - загрузка, публикация результатов и инвентаризация S3;
- `src/verify_results.py` - полная сверка выходных JSON;
- `src/profile_pipeline.py` - измерение времени и пикового RSS;
- `scripts/validate_rustfs.ps1` - полный сценарий проверки;
- `evidence/rustfs-validation/` - журналы и результаты реальных запусков;
- `report/build_report.py` - сборка PDF из результатов и иллюстраций.

## Текущие ограничения

В выбранных вакансиях 4 266 записей содержат навыки, а 1 364 раскрывают зарплату.
Медианы по регионам также опираются на разное число зарплатных наблюдений.
Неучтённые различия в должности, опыте, компании и отрасли могут влиять на
зарплаты и популярность сочетаний. Официальное определение варианта 11 следует
сверить с текстом задания преподавателя.
